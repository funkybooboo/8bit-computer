# roms/ - archived EEPROM images

The EEPROM contents used by the machine - the browsable archive of what
is burned. Computer.dig carries the same data inline (circuit attribute
`romContent`), kept in sync by the tooling.

| file                       | chip (in Computer.dig) | preset            |
|----------------------------|------------------------|-------------------|
| output-display.hex         | U45                    | output-display    |
| output-display-intel.hex   | U45                    | output-display    |
| control-rom1.hex           | U47                    | control-rom1      |
| control-rom1-intel.hex     | U47                    | control-rom1      |
| control-rom2.hex           | U52                    | control-rom2      |
| control-rom2-intel.hex     | U52                    | control-rom2      |

`*.hex` are Logisim format ("v2.0 raw" + hex words), loadable by Digital's
ROM editor; `-intel` variants are Intel HEX for EEPROM burners.

What the images mean: the control ROMs are the microcode
([../docs/microcode.md](../docs/microcode.md)); the display ROM is the
output module's digit patterns ([../docs/hardware.md](../docs/hardware.md),
output register). The contents are defined and generated by
[../tools/microcode.py](../tools/microcode.py):
`tools/microcode.py --generate` writes these files, `--check` verifies
them, and every build uploads them its own way (Digital via
../digital/digrom.py, the web build by fetching them, the hardware by
burning the Intel HEX files); how to re-inject into Computer.dig:
[../docs/tools.md](../docs/tools.md).
